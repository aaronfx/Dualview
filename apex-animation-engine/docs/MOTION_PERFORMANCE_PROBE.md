# APEX — The Threshold: motion-performance benchmark

## The problem it tests

Previous APEX action films could be **technically valid yet emotionally and visually stiff**. The owner rated an earlier core engine ~8.5/10 for mechanics and ~6.8/10 for presentation. Better physics alone does not guarantee compelling animation.

The purpose here is to force APEX to present a *single readable intention*, a motivated decision, a real physical obstacle, and an earned payoff in a short original film.

### Original story / four shot grammar
1. **Doubt:** IKO sees a heavy slab blocking the path to a glowing plus-sign object. He double-takes and physically recoils.
2. **Commitment:** a decision builds from an eye move and backward recoil into a leg-loaded crouch and forward lean; running begins only when the pose releases.
3. **Leap / absorption:** IKO clears the existing rigid physical obstacle under gravity and lands; the existing high-quality APEX landing performance handles contact.
4. **Recovery / reward:** hands plant against knees while breathing and looking back; the actor rises and moves to physically retrieve the glowing sign, then celebrates.

### New reusable clips
- `motion/clips/doubt_to_dash.json`: eye focus → recoil → anticipation → body weight load → release. Named keyposes and phases, no hard-coded frame offsets.
- `motion/clips/impact_to_grin.json`: landed weight → breath → gaze → settle, including **actual IK contacts** to the knees during recovery.

Both are available to any APEX project via `{"type": "act", "clip": "..."}`. Their rigs remain character-agnostic.

### Engineering acceptance

- Builder `examples/build_motion_performance_probe.py` simulates Pymunk/Chipmunk before writing a storyboard.
- It rejects missing or badly ordered `takeoff`, `impact` and `pick_up` physics events.
- Four camera cuts come from actual simulated event times, with minimum shot durations.
- Native scene goals verify notice, clip start, takeoff, impact, recovery clip and physical glyph pickup.
- Code-level tests check expressive contrast in clip channels (not a claimed visual review score), contact targeting and deterministic storyboard.
- `apex render` produces an MP4 with technical QA and review sheet; the actual MP4 must decode and have stable sync before approval.
- Human reviewers must see distinct acting, planted weight and motivation at normal speed. A score is never generated by tests.

### Repeatable Windows commands

```powershell
cd apex-animation-engine
python -m pip install -e ".[dev]"
python -m pytest -q tests/test_motion_performance_probe.py
python examples/build_motion_performance_probe.py out/threshold_performance.json
apex render out/threshold_performance.json -o out/threshold_performance.mp4 --scale 0.75 --samples 1 --qa-json out/threshold_qa.json --review-dir out/threshold_review
apex review out/threshold_performance.json out/threshold_review --video out/threshold_performance.mp4 --qa-json out/threshold_qa.json
```

A GitHub Actions workflow `apex-motion-performance-preview.yml` runs the test, build, render and review packet, retaining the MP4/QA/contact sheet as one artifact.

### Mandatory human review after each render

Watch without sound: can a new viewer identify the slab as the challenge, the intended reward, the moment of decision and the result? Then watch with sound at normal speed, and frame-step the anticipation, takeoff, impact, recovery, pickup. Reject clips if foot/hand contact floats, the leap feels unpowered, the camera does not convey space, or the payoff is weak. Record timestamps and targeted fixes using `docs/REVIEW_RUBRIC.md`, never claim to have achieved the reference video quality merely because tests pass.

### Next iteration if this passes

Test three physically different movements with the same clip vocabulary (flat floor, slope, raised platform), vary body proportions, add two-character reaction timing and handoffs, and improve shot composition. Move to autonomous selection of animations only after these primitives perform well under human review.
